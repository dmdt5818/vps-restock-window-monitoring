## VPS 补货是什么，为什么总是上架即售罄

补货指的是商家把之前售罄的特价套餐重新上架，通常限量、售完即止，续费价和首单价一致。圈内把这种锁价年付套餐叫“传家宝”，价格锁死、长期有效，所以每次补货都有一批人是专门来囤货的。

断货的原因很具体，三个叠在一起：

- 香港、日本这类热门机房的上游机柜资源紧，商家补货要排队，上架就售罄
- 优化线路本身成本高，商家不会无限量放货，限量补货是常态
- 新用户首购和老用户复购撞在同一时间点，热门套餐几分钟内就被抢光

“售罄”只是当下的库存状态，不代表这条产品线下架了。它在等下一批资源。

## 补货窗口有多长，第二次机会从哪来

3 到 10 分钟是补货后可下单的实际时间。这个窗口里你要完成登录、选配置、填优惠码、付款，任何一步卡住就出局。第二次机会来自未支付订单的库存释放，这部分回流往往没人盯，5 到 10 分钟后再刷两轮，命中率不低。

通知到付款之间，能提前做的有四件：

1. 账号注册完、邮箱验证过，别等到下单页才发现验证邮件没点
2. 浏览器保存登录态，密码管理器自动填充
3. 结算页支持的支付方式提前确认，设成默认
4. 心仪机型的商品页单独加书签，通知来了直接进商品页，不从首页慢慢找

## 监控怎么设：三种方案，按上手难度排

**官方渠道优先。** 商家普遍用 Telegram 频道发补货通知，通常就是一句“XX 服务已大量补货”。订阅零成本，建议设为静音但不屏蔽，或者直接置顶。AkkoCloud 官网公告里放了售前 TG 交流群入口，售后走工单系统，没有单独的补货播报频道，所以用第三方聚合或自建监控更稳一些。

**第三方聚合站被动接收。** 这类站点直接读商家官网库存，一家一家抓。以 VPS叮 为例，2026 年 11 月 12 日 13:55 的页面口径是收录 18 家商家、861 款套餐、477 款有货，其中 757 款月付在 $20 以内；更新频率快的几十秒一次、慢的几分钟一次；提醒方式有浏览器网页推送、Telegram 机器人私信和一个补货频道。价值在于一次订阅覆盖多家，缺点是二手抓取，价格与库存仍以商家页面为准。

**自建监控主动出击。** 技术党可以基于 changedetection.io 盯商品页按钮，从“Out of Stock”变成“Order Now”就推送到 Telegram、Discord 或邮件。比纯 HTML diff 更准的做法是用 Node.js + Puppeteer 这类脚本，按自定义规则识别按钮文本变化，误报率低一截。

如果你翻到的是老教程里的 Python 方案，有三处要留意：

- 那套脚本作者原文只列举了 9 家商家，网上流传的“数十家”是标题写法，实际覆盖范围以那段列举为准
- 教程里的 crontab 写 `*/10 * * * *`，正文解释成“每 10 秒执行一次”。这个表达式实际是每 10 分钟一次，要秒级得换调度器
- 技术栈是 Python 2.7 + MySQL 5.5+，现在跑建议用 Python 3 重写
